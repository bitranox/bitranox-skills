# Skill-writer checklist: meta-context-watcher "what next" trigger (2026-09-24)

Scope: the frontmatter `description` only. The reading clause gains "or is asked what to do next"
and two quoted triggers, "what next" and "what's next for <project>". Every existing trigger stays.
The body already covers the case: its reading section says the backlog, read first, decides what
is worth doing next. Tested as a ROUTING change, like the reading-trigger edit before it. The
question is whether a router judging from descriptions offers the skill, not whether an agent
follows the body.

The test was pre-registered before any run: arms, sets, a pass rule per criterion, and an
UNDERPOWERED branch for too few positive rows.

## RED (shipped description)

- [x] Router RED: on 10 fresh "what next"-style prompts (no text shared with any earlier set), the
      Jev router (choice_full, installed roster, gate 0.5, shipped pick rule) caught
      context-watcher on 2 and 3 of the 10 the blind panel says need it. That is two interleaved
      runs, A B A B.
- [x] Native arm: four haiku `baseline-probe` routers were given a 10-skill listing. The skill was
      renamed `session-continuity`, and `process-plan-brainstorming` (the Jev runner-up on these
      turns) was added. Given the shipped wording, they routed 10/10 and 8/10 of the same prompts to
      the skill. So Claude Code's own routing mostly handled these turns ALREADY, and this arm is
      near ceiling. It cannot show a gain; it can only show harm.
- [x] Inherited-coverage check: not applicable to the router arm, whose model never sees this
      machine's CLAUDE.md cascade or memory. The native arm used a renamed skill and a pasted
      listing.

## REFACTOR

- [x] GREEN diffed against RED in both directions, row by row. Right picks moved 23 -> 28 on cw2,
      14 -> 16 on the first-50 set, and 11 -> 11 on the held-out 50. On cw1 they moved 24 -> 23,
      and one wrong pick went 1 -> 0. Two rows lost a right pick. Both sets were re-run with
      everything else fixed, so they were no longer single runs:
      - cw2 "gate, push, then write the handover": NOISE. The shipped wording itself flips between
        context-watcher and `tfbpr` across runs. The set-level gain reproduced: context-watcher was
        right 22 and 21 times in A against 27 and 26 in B.
      - cw1 "whats open ?": REAL, 3 of 3 reps. The winner is still context-watcher, but its
        probability falls from 0.78-0.88 to 0.55-0.69 while `none_needed` rises. The gate is about
        0.4 in both arms, so the pick now misses the 0.7 confidence bypass. DECLINED as a like-for-like
        trade. It costs one context-watcher pick of the same value as the 13 to 14 gained across
        the sets, and recovering it would mean a further wording fitted to prompts that have now been
        read. It needs a set it was not written from.
- [x] Criterion 3: the new wording made 8 new context-watcher picks on guard rows whose earlier
      panels had not labelled them as wanting it. Those panels had the OLD description visible.
      The 8 rows, plus 3 unrelated no-skill controls, went to a fresh blind panel of five judges
      with the neutral summary. Result: 6 unanimous right, 2 unanimous defensible, 0 wrong. All 3
      controls came back wrong by majority, so the panel could say wrong. The pass rule allowed at
      most 1 wrong.
- [x] DECLINED: widening the wording further, for example to a bare "continue". That is a different
      turn class that the reading section does not own. Any further wording needs prompts it was
      not written from.
